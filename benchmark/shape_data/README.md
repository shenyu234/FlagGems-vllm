# Qwen3.6 MThreads full-shape tests

The frozen dataset contains 562 distinct cases (TP1: 275, TP4: 287) collected
from Qwen3.6-35B-A3B. Each record preserves Q/K/V shapes, cumulative Q lengths,
used KV lengths, page size, case ID, category, trace provenance and frequency.

These cases use the current benchmark input policy: derive host length maxima
and block-table width from actual lengths, and use `num_splits=0`. Original
trace hints remain under `trace_metadata`. Do not replace actual lengths with
those hints. Page-table entries and Q/K/V values are generated by the original
benchmark input function; this dataset is not a dump of tensor values.

The default benchmark remains the existing 12 cases. Select the full dataset:

```bash
export MTHREADS_FA_SHAPE_SET=full  # also: tp1-full, tp4-full
python -m pytest -q -s benchmark/test_flash_attn_varlen_func.py \
  -p _cudagraph_plugin --mode cudagraph --dtypes bfloat16 \
  --warmup 1000 --iter 100
```

Select exact IDs with `MTHREADS_FA_CASE_IDS=id1,id2`. Unknown and out-of-set IDs
raise an error. Full-shape input seeds are `20261008 + crc32(case_id)`.

Run full numerical validation separately:

```bash
MTHREADS_FA_SHAPE_SET=full python -m pytest -q \
  tests/test_flash_attn_varlen_mthreads_full.py
```

The full numerical test is opt-in and MThreads-only. It compiles production
kernels before execution, requires spill <40, checks complete O/LSE, and
checks two Graph replays after filling output buffers with NaNs. Set
`MTHREADS_FA_VALIDATION_OUT` to a fresh directory to retain per-case JSONL
results. O tolerances remain atol=rtol=.02; LSE tolerances remain .002.

The numerical oracle is MATE through the existing native wrapper. In the new
development container, use the project's isolated native-reference copy for
validation only. Causal all-masked rows retain the existing O=0/LSE=+inf
contract; the test checks native O=0 and infinite LSE before normalizing the
native LSE sentinel. This is native-reference agreement, not a separate full
FP32 mathematical proof.

Measure native C in `zhangshen_vllm0.24.1` with `--metrics latency_base` and
Triton in `zhangshen_vllm0.24.1_triton3.6` with `--metrics latency`, sequentially
on an idle GPU. Match by case ID/shape and report old-container
`latency_base / new-container latency`; do not use the new container's native
column as the baseline. Numerical failures must remain visible and cannot
count as performance acceptance. Existing container dependencies and the
Graph timing plugin must be preserved.

Source: local MetaX evidence `flaggems_vllm_full_auto_bf16/selected_cases.json`.
The imported record contents are unchanged; only JSON formatting and the
TP1/TP4 file split differ.
